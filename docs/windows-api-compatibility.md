# Windows x64 API compatibility audit

Updated: 2026-10-03

Scope: FSTR Stretch / ElasticGridFX Windows x64 CPU port on
`feat/windows-x64-aex`. This is a **static compatibility audit** under
AE-Development-Rules 6.2.0. It is not After Effects runtime evidence.

## Declared target

- Working runtime target for validation: After Effects 2025+ on Windows x64.
- Candidate lower static floor under investigation: After Effects 23.4.
- Windows GPU is out of scope.
- No merge, release, publication or installation is authorized by this record.

## Build/binding baseline

The Windows artifact builds with:

- target `x86_64-pc-windows-msvc`;
- Rust `after-effects = 0.4.0` / `after-effects-sys = 0.4.0`;
- built-in Windows bindings when `AESDK_ROOT` is unset;
- PiPL Effect API declaration `13.28`;
- MSVC x64 and the exact toolchain recorded in each Build Identity.

The external Adobe SDK is therefore **not** a compile-time dependency of the
current normal Windows build. Supplying `AESDK_ROOT` selects regenerated
bindings and is a different build configuration requiring separate evidence.
`AESDK_ROOT` participates in the Build Identity settings hash so that override
cannot silently reuse the normal built-in-bindings Build ID.

## API/version findings

| Contract | Revision used | Minimum/source finding | Status |
|---|---:|---|---|
| Effect API / PiPL | 13.28 | The pinned Rust AE examples map 13.28 to After Effects 23.4 or later. | STATIC-COMPATIBLE for 23.4+ |
| AEGP Utility Suite | 6 | Adobe SDK guide history states UtilitySuite6 was introduced in AE 14.2. | STATIC-COMPATIBLE below current floor |
| AEGP Stream Suite | 6 | Adobe SDK guide states StreamSuite6 is available in AE 22.5 and later. | STATIC-COMPATIBLE below current floor |
| AEGP Keyframe Suite | 5 | The project handoff records AE 22.5 as the minimum, but the current public Adobe guide page does not state the Suite5 introduction version explicitly. | UNKNOWN introduction date; no blocker above 23.4 identified |
| Smart Render / MFR | threaded-rendering flags + flattened sequence data | Adobe guide documents the March 2021 sequence-data/MFR contract for AE 22-era builds. | STATIC-COMPATIBLE below current floor |
| Windows entry point | `CodeWin64X86("EffectMain")` | Exact Windows PE CI verifies x64 PE, exported `EffectMain`, and byte-exact PiPL resource. | Build/static PASS; runtime NOT RUN |

## Source inventory

Host-facing source is concentrated in:

- `host-rust/src/lib.rs`: PF effect entry point, parameters, SmartFX/MFR flags,
  UI event dispatch and render selectors;
- `host-rust/src/lifecycle_probe.rs`: AEGP registration, UtilitySuite6 idle wake
  and deferred auto-binding;
- `host-rust/src/binding_probe.rs` / `binding_transaction.rs`: Stream/Keyframe
  access and transactional expression/binding changes;
- `host-rust/src/plane.rs`: PFInterface/Layer access for plane/UI state;
- `host-rust/src/ui.rs`: Custom UI and cursor events.

The pinned wrapper source confirms the concrete suite revisions used by those
wrappers. The exact lower host version still depends on all called suite
revisions and host behavior, so 23.4 is not promoted to VERIFIED without runtime
evidence.

## Windows platform findings

- CPU rendering uses the non-Apple `std::thread` path.
- x64 SIMD uses the existing SSE path selected by `_M_X64`.
- Metal/AppKit/Objective-C++ sources remain macOS-only.
- Windows cursor handling uses AE built-in Hand/Pan cursors.
- Windows lifecycle main-thread identity is captured at `GlobalSetup` before
  AEGP registration/idle work. Adobe documents `PF_Cmd_GLOBAL_SETUP` and
  `PF_Cmd_GLOBAL_SETDOWN` as main-thread-only, while sequence/render selectors
  may be concurrent under MFR. AEGP calls remain main-thread/idle-only; only
  `AEGP_CauseIdleRoutinesToBeCalled()` is documented thread-safe.
- The published `pipl 0.1.1` Windows resource emitter corrupts bytes >= 0x80
  when Custom UI is present. The branch keeps the existing dependency for macOS
  and applies a local Windows-only compatibility shim equivalent to upstream
  fix `83dcc93734fd5db1335b6ec83cba7a6505a39dcc`.

## Exact build evidence

Windows build/static evidence is generated by `.github/workflows/windows-port.yml`.
For each candidate it records:

- portable C++ tests;
- Windows Rust host tests;
- Windows Clippy with warnings denied;
- release cdylib build;
- x64 PE header;
- `EffectMain` export;
- PE imported-symbol and dependent-DLL inventories;
- PiPL resource presence and byte-exact comparison;
- Build ID, commit and artifact SHA-256.

These checks do **not** prove After Effects load, UI, auto-binding, Undo, MFR,
Render Queue, `aerender`, save/reopen, or performance.

## Remaining compatibility gates

Before any supported-version claim:

1. run the exact AEX in the selected AE 2025+/25.x Windows build;
2. verify loaded module identity, UI, render and save/reopen;
3. run cold-start first-application matrix;
4. verify interactive guide drag + Undo/Redo;
5. verify Render Queue, MFR and `aerender`;
6. if AE 23.4 is to be advertised as supported, run that exact version too.

Until then, do not label any Windows AE version VERIFIED.
